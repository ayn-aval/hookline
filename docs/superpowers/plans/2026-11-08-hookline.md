# Hookline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a re-runnable tool and Streamlit app that reads a microdrama's timestamped screenplays and returns ranked 20–60 s promos (continuous and stitched), with segment timestamps, hook, cliffhanger and why.

**Architecture:** A deterministic parser turns scripts into beats with IDs. LLM stages (series bible, per-episode mining, cross-episode stitching, cold-viewer judging) refer only to beat IDs. Code validates, snaps and ranks. A thin OpenAI-compatible client makes the model swappable. The CLI and the Streamlit app share `hookline.pipeline.run_pipeline`.

**Tech Stack:** Python 3.12 (uv), `openai` SDK (Gemini OpenAI-compatible endpoint), `pydantic` v2, `streamlit`, `pytest`. The PDF is rendered from HTML with headless Chrome.

**Spec:** `docs/superpowers/specs/2026-11-08-hookline-design.md`

**Execution method chosen:** Native (the user went away and granted full autonomy). Each task ends in its own commit.

## Global Constraints

- Promo total duration: **20–60 s**. Hook must start **≤ 3.0 s** after the promo start. The cliffhanger beat must end within **1.0 s** of the promo end.
- LLM output may reference **beat IDs only** (`E07-B031`). Timestamps come from the parser.
- Never cut mid-dialogue: a segment boundary that lands inside a DIALOGUE beat extends to cover the whole beat.
- Default provider `gemini`, model `gemini-3.5-flash`. Base URL `https://generativelanguage.googleapis.com/v1beta/openai/`. Env vars: `HOOKLINE_PROVIDER`, `HOOKLINE_MODEL`, `HOOKLINE_API_KEY` (falls back to `GEMINI_API_KEY`), `HOOKLINE_BASE_URL`.
- Every LLM call is cached on disk, keyed by sha256 of (model, messages), under `<out>/raw/`. That folder is also the "raw outputs".
- The input pack (screenplays) is never committed: `data/` is gitignored. Committed outputs contain no script text beyond the hook and cliffhanger quotes.
- Commits use the repo-local identity `ayn-aval <lavanya.nair.bce22@itbhu.ac.in>`. Global config is never touched.
- Solution PDF: at most 2 pages.

## Review Focus

1. **A new show whose format differs slightly** (missing logline, extra whitespace, `Start: (1:02.5)` without a leading zero, a speaker with no emotion parenthetical). The parser must parse what it can and record warnings, never crash. Owned by Task 1 (`test_parse_tolerates_variants`).
2. **The LLM returns unknown or reversed beat IDs, or bad JSON.** The candidate is rejected and logged, and the run continues. Owned by Task 3 (`test_validate_rejects_unknown_beat`, `test_validate_rejects_reversed_segment`) and Task 2 (one JSON-repair retry).
3. **Rate limits (HTTP 429) on the free tier mid-run.** Back off and retry. Cached calls are not re-billed when the run is restarted. Owned by Task 2 (`test_cache_hit_skips_call`).
4. **Overlapping beats at a cut point** (a camera beat ending mid-line). The end snaps to the end of the dialogue line. Owned by Task 3 (`test_snap_extends_over_dialogue`).
5. **A stitched promo whose segments overlap each other or total under 20 s.** It is repaired or rejected. Owned by Task 3 (`test_validate_duration_bounds`).

The text is the following non-empty lines up to the next header. Labels `CAMERA`, `ACTION` and `SOUND FX` map to their kinds, and anything else maps to DIALOGUE with the quotes stripped. The episode number comes from `EPISODE NUMBER: Episode N`, falling back to the filename.

### Task 3: Validate, snap, dedupe, rank (pure code)

**Files:**
- Create: `hookline/validate.py`, `hookline/rank.py`
- Test: `tests/test_validate.py`, `tests/test_rank.py`

**Interfaces:**
- Consumes: `Beat` and `Episode` (Task 1).
- Produces:
  - `SegmentRef(start_beat:str, end_beat:str)`
  - `Candidate(id:str, kind:'continuous'|'stitched', segments:list[SegmentRef], hook_beat:str, cliff_beat:str, hook:str, cliffhanger:str, why:str, title:str, context_needed:str='')`
  - `Segment(ep:int, start:float, end:float, start_beat:str, end_beat:str)`
  - `Promo(id, kind, title, segments:list[Segment], duration:float, hook, cliffhanger, why, hook_beat, cliff_beat, repaired:bool, scores:dict={}, rank:int|None=None, post_reason:str='', final_score:float=0.0, spoiler:int=0)`
  - `validate_candidate(c:Candidate, index:dict[str,Beat]) -> tuple[Promo|None, list[str]]` (returns the promo or `None` with reasons, plus repair notes)
  - `dedupe(promos:list[Promo], iou:float=0.5) -> list[Promo]`
  - `rank_promos(promos:list[Promo], n_episodes:int) -> list[Promo]` (sets `final_score`, `rank` and `post_reason`)

- [ ] Step 1: Write the tests.
  - `test_snap_extends_over_dialogue`: a segment end at a camera beat inside a dialogue beat extends to the dialogue's end.
  - `test_validate_rejects_unknown_beat`
  - `test_validate_rejects_reversed_segment`
  - `test_validate_duration_bounds`: 15 s is rejected; 65 s is trimmed from the front only if the hook stays ≤ 3 s, otherwise rejected; 40 s passes.
  - `test_hook_within_3s`: a hook beat starting 5 s in moves the segment start to the hook start (repair) if the duration stays ≥ 20 s.
  - `test_cliff_at_end`: if the cliffhanger beat isn't within 1 s of the end, the end is trimmed to the cliffhanger's end if the duration stays ≥ 20 s, otherwise rejected.
  - `test_dedupe_iou`
  - `test_rank_orders_by_score_with_funnel_and_diversity`: with equal judge scores, the earlier-episode promo ranks higher, and two promos from the same episode aren't adjacent when an alternative exists.
- [ ] Step 2: Run the tests. They should fail.
- [ ] Step 3: Implement.
  - Durations are measured from segment start to segment end, summed over segments.
  - Ranking score: `final = 0.30*hook + 0.25*cliff + 0.25*standalone + 0.20*emotion` (judge 1–5), plus `0.3` if the duration is within 30–45 s, minus `0.6*spoiler`, minus `0.4*(min_ep-1)/(n_eps-1)` as the funnel term.
  - Order: a greedy pass picks the highest remaining score, but skips a promo whose primary episode equals the previous pick's when another promo within 0.25 of its score exists.
  - `post_reason` is generated by a template from the top contributing factors.
- [ ] Step 4: Run the tests. They should pass.
- [ ] Step 5: Commit `feat: validation, snapping and ranking`.

### Task 4: Prompts + pipeline + CLI, smoke run on 3 episodes

**Files:**
- Create: `prompts/bible.md`, `prompts/mine_episode.md`, `prompts/stitch.md`, `prompts/judge.md`, `hookline/pipeline.py`, `hookline/baseline.py`, `hookline/report.py`, `hookline/cli.py`, `hookline/__main__.py`
- Test: `tests/test_pipeline.py` (fake LLM, end to end on 2 tiny episodes)

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - `run_pipeline(show:ParseResult, llm:LLM, out_dir:Path, progress:Callable[[str,float],None]|None=None, max_workers:int=4, episodes:list[int]|None=None) -> RunResult`
  - `RunResult(promos:list[Promo], bible:dict, meta:dict)`
  - `write_outputs(result, show, out_dir)`, which writes `promos.json`, `promos.csv`, `report.md` and `run_meta.json`
  - `baseline_promos(show) -> list[Promo]` (last ~45 s of each episode, snapped)
  - CLI: `python -m hookline run --input PATH --out DIR [--provider --model --episodes 1-3 --workers 4]` and `python -m hookline eval --out DIR`
- Prompt contracts (the JSON keys the code reads):
  - bible: `{premise, characters:[{name, aliases[], role}], arcs[], reveals:[{reveal, episode}]}`
  - mine: `{candidates:[{title, start_beat, end_beat, hook_beat, cliff_beat, hook, cliffhanger, why, context_needed}], moments:[{beat, type:'hook'|'cliff', note}]}`
  - stitch: `{promos:[{title, segments:[{start_beat,end_beat}], hook_beat, cliff_beat, hook, cliffhanger, why}]}`
  - judge (batch of ≤ 8): `{scores:[{id, hook, cliff, standalone, emotion, spoiler, cold_viewer_summary, weakness}]}`
- Mining sends the beats compactly. CAMERA beats are truncated to 120 characters; DIALOGUE, ACTION and SFX are sent in full.

- [ ] Step 1: Write `test_pipeline_end_to_end_fake_llm`. With a fake LLM that returns canned JSON keyed by tag, `run_pipeline` returns ≥ 1 promo whose timestamps exist in the parsed beats, and the output files exist.
- [ ] Step 2: Run it. It should fail.
- [ ] Step 3: Implement the prompts and pipeline:
  - Mining runs in a `ThreadPoolExecutor(max_workers)`.
  - The stitch stage gets a moment catalogue: each moment beat with its line text and ±1 neighbouring beat of context.
  - The judge sees only the promo's beats text, in play order.
  - Spoiler = max(judge spoiler, 2 if any segment is at or after a bible reveal episode and the promo text mentions the reveal keywords, else 0).
  - `meta` records counts (candidates, valid, repaired, rejected with reasons), tokens, the cost estimate at $0.30/M input and $2.50/M output (to be documented as an assumption), timings, model and the prompt sha.
- [ ] Step 4: Run the tests (they should pass), then the live smoke test: `python -m hookline run --input data --out outputs/smoke --episodes 1-3`. Inspect `report.md` by hand and tune the prompts if the picks are poor.
- [ ] Step 5: Commit `feat: LLM pipeline, CLI and outputs` (`outputs/smoke` is gitignored).
